# v0.2.1 · 2026-09-30

## 更新内容

- **新增自定义源**：设置 → 订阅源设置 →「＋ 添加自定义源…」，粘贴任意 RSS/Atom 地址（可一次贴多行）即用。
  名称自动取 feed 标题，可重命名、调条数、切换「用 feed 摘要 / 逐篇抓全文」、测试可达性、删除
- **修一批正文丢失的问题**：代码块、表格、引用块此前会**整块消失**——技术类文章（博客园/掘金/美团/InfoQ）受影响最大，
  实测某篇博客园文章正文 8.4KB 全在表格里，修复前只抓到 2143 字、修复后 12061 字
- **文章改为按时间从早到晚排列**（此前是最新在前）
- **新增阅读排版**：设置 → 阅读排版，可选「紧凑 / 标准 / 宽松」（段间距与行距）；
  正文左右留白收窄，代码块/表格/引用块有了专门的样式，链接改为可辨认的蓝色下划线
- **修 RDF 源多出一条幽灵条目**：某些源（如 Slashdot）会混进一条标题是站点名的假条目
- 菜单「往期缓存」改名为「缓存期刊」；抓取进度不再显示耗时（更清爽）

## 升级方式

设置 → 检查更新 →「更新到 v0.2.1」。

# v0.2.0 · 2026-09-30

## 更新内容

- **设置菜单重整**：从 10 项平铺改为 6 项分组——图片显示 / 订阅源 / 缓存清理 / 检查更新 / 收藏 / 诊断
- **新增「图片分辨率」**：可选「自动（按屏幕宽度）」或 480 / 600 / 800 / 1000 / 1200 / 1600 px。不同设备屏宽不同，这里可各取所需；改档位后当天缓存自动清空，下次抓取生效
- **源连通性自检**：改用与「检查更新」同款的进度条，探测移到子进程——**界面不再假死，点击即取消**（连域名解析卡住也能中断）
- **诊断更可靠**：网络诊断修好 TLS 握手判定与取消；新增「重新允许 gzip 压缩」，万一压缩功能被误判停用可一键恢复
- **一批健壮性修复**（共 14 项）：
  - 更新：下载异常时不再毫无提示；安装阶段禁止取消（避免插件目录被删空）；点击进度条不再误触下层菜单
  - 网络：失败重取不再丢失证书校验；压缩解压的熔断只对真正的平台故障生效（个别数据损坏不会让设备永久降级）
  - 阅读：改图片/订阅设置不再删除**正在阅读**的那一期；菜单勾选项点击即时刷新
  - 图片：分辨率提高时整期图片额度同步放大（不会"越清晰图越少"）；超高图有专门的小尺寸兜底；同一张图在多篇文章里只存一份
  - 提示：「N 张图未取到」按真实原因显示（过大 / 额度已满 / 图床不可用），不再重复累加
- **改个名**：菜单「往期缓存」→「缓存期刊」

## 升级方式

设置 → 检查更新 →「更新到 v0.2.0」。

若当前版本已无法联网抓取（更新检查也打不开），把下方 ZIP 解压后覆盖 `plugins/zhifou.koplugin/` 即可。

# v0.1.20 · 2026-09-30

## 更新内容

- **修「部分设备所有源都抓不到」**：v0.1.15 起的 gzip 压缩在 zlib 不完整的设备（如 Boox Nova3）上会抛错并中断整个请求 → 现在会先探测实际可用的解压能力，不可用就走明文；异常也不再外泄。

- **新增两个诊断入口**：设置 →「网络诊断（分阶段）」「最近错误（诊断）」——以后设备上抓不到东西，屏幕上就能看到卡在哪一步。

# v0.1.15 · 2026-09-30

## 升级方式

KOReader 里打开 **知否 → 设置 → 检查更新**，会显示「更新到 v0.1.15」，点击即可自动下载安装（直连不通时自动走镜像），装完重启 KOReader 生效。也可以下载下方 ZIP 手动放进 `koreader/plugins/`。

装过 v0.1.14 的直接升即可；v0.1.13 及更早也能升（更新器兼容新旧两种目录名）。

---

## 重点：抓取不再卡住

### 「读首诗再睡觉」每次抓取卡一两分钟 — 已修

查出来的原因是它家的 feed 有 **2.01MB**（WordPress 把每首诗全文，含两三万字的赏析，都塞进了 feed），而插件此前从不告诉服务器"我支持压缩"，于是每次都老实下满 2MB。设备端单次请求的总超时是 30 秒，弱网（≈60KB/s）下需要 **32 秒** → 超时失败 → 自动重试 4 次 → **卡约两分钟**。

这一版让所有请求都声明支持压缩，服务端压完只有 **204KB**：

| | 下载量 | 用时 | 结果 |
| --- | --- | --- | --- |
| 改前 | 1.92MB | 32.0 秒 | ✗ 超时 → 重试 ≈ 卡两分钟 |
| 改后 | 204KB | **4.3 秒** | ✓ 通过 |

所有源都受益（IT之家、虎嗅等 feed 同样被压缩传输），实测一期抓取从"最慢的源拖后腿"变成整体约 1 分钟。

### 一个坏源不再拖垮整期

- 新增**整期抓取时间预算**（300 秒）：超时自动跳过剩余源，并在完成提示里写明「抓取超时已跳过 N 个源」
- 新增 408/425/429 重试，遇到 **429 限流会听服务端的 `Retry-After`**（最长等 10 秒）
- 重试间隔改为指数退避（0.5/1/2 秒）加随机抖动，多个源同时失败也不会一起重试
- 给所有响应加了**字节上限**（图片 3MB、其它 8MB），异常大响应会被就地中断，不再可能把内存撑爆

## 不再产出「只有标题」的空文章

抽取器现在会自检：如果定位到的正文容器里明明有大段文字，但抽出的正文不到 5%，就判定为"站点改版导致抽取失效"，**自动回退到 RSS 摘要**并记日志——以前这种情况会安静地产出一篇只有标题的空白文章。

实测 6 个需要抓正文的源（少数派、量子位、InfoQ、快科技、9to5Mac 等）正常保留率在 15%~85%，阈值留足了余量，不会误伤。

其它同类修复：

- RSS 里的非法时间（如 `2026-13-45`）不再被静默"进位"成错误日期，按无时间戳处理
- 知乎日报某一篇正文抓取失败时跳过该篇继续，不再整天没内容
- Readhub 早报改为按结构校验条目区段，站点改版后文末的推荐位不会再被当成正文吸进来

## 在线更新的安全加固

更新器下载的是**要执行的代码**，这一版给它补上了两道锁：

- **TLS 证书校验**：更新链路的 API 请求与安装包下载都启用证书校验（用 KOReader 自带的 CA 库）
- **安装包 SHA256 校验**：从 GitHub 拿到官方摘要后逐字节比对；对不上就删掉、自动换下一个镜像——国内镜像回退是日常路径，这道校验能挡住被投毒的镜像

实测：正常下载通过校验（与 GitHub 报告的大小、摘要一致），把包里改一个字节会被正确拒绝。

## 更快、更好排查

- **新菜单：设置 → 源连通性自检**。一次列出每个已订阅源是否可达、各花多少秒、最慢的是哪个，不用再"改设置→抓一次→看谁失败"来回试（自定义源会标注跳过）

  实测：13 个启用源中可达 11 个，最慢为「读首诗再睡觉」9.1 秒（与其 feed 本身响应慢相符）
- 收藏索引与条目侧车文件加了**解析缓存**：打开首页与阅读器内「⋯」菜单时不再重复解析同一份文件，低配设备上更跟手

# v0.1.14 · 2026-09-30

## 升级方式

KOReader 里打开 **知否 → 设置 → 检查更新**，会显示「更新到 v0.1.14」，点击即可自动下载安装（国内直连 GitHub 不通时自动走镜像），装完重启 KOReader 生效。也可以下载下方 ZIP 手动放进 `koreader/plugins/`。

---

## 本版重点：一期体积降到原来的 1/5 左右

来源站的图片原本是「原图直下」，一期动辄 22–34MB。这一版把图片链路整个重做：

- **按图床套 CDN 缩放**（宽 800，超高图自动降到 480）
- **PNG/GIF 让 CDN 直接输出 JPEG**（这部分是体积大头）
- **默认转灰度**（墨水屏上彩色没有意义；`设置 → 图片转灰度（省体积）` 可关）

实测（同一批 200 张真实图片）：**81.1MB → 13.3MB，省 84%**。几个典型单张：

| 图片 | 处理前 | 处理后 |
| --- | --- | --- |
| 知乎动图（GIF） | 8.6MB | 19.7KB |
| 知乎动图（GIF） | 4.6MB | 59KB |
| 「一个」配图 | 792KB | 37KB |
| 虎嗅截图（PNG） | 1.14MB | 141KB |
| 少数派截图（PNG） | 100KB | 22KB |

模拟器实抓一期验证：**10.5MB / 281 页 / 151 张图**（旧版同规格一期为 22.5–34MB）。

另外加了体积闸门，避免个别巨图把整期撑爆：单张 ≤1.5MB、整期 ≤12MB、张数 ≤150；超限会先降档重试，仍超则略过并在完成提示里写明「N 张图过大已略过」。

## 阅读正确性（EPUB 合规）

- 正文图片**逐张登记进 OPF manifest**（旧版一张都没登记，用 epubcheck 校验是不通过的）
- 补上 EPUB 3 必需的 `dcterms:modified`；`identifier` 带上期号（旧版同一天的各期 ID 完全相同）
- 修正 NCX 目录的 `playOrder` 顺序（旧版父节点编号晚于子节点，文档流非单调）
- 剥离正文里的 XML 非法控制字符（源站偶发带入，会让整篇文章成为非法 XML）
- 封面不再重复存一份：封面取自正文首图时直接复用该图，每期省下一张最大的图

## 数据安全

- **缓存命中要求文件完整**：写盘中断留下的截断 EPUB 会被识别并重新抓取（旧版会当成有效缓存，打开报 invalid document 且永不重抓）
- **写盘失败会被发现**：`flush`/`close` 出错时删掉半成品并报错，不会把截断文件改名成正式期文件
- **收藏索引损坏不再静默清空**：先把原索引备份为 `favorites.lua.broken-<时间戳>`，并在首页提示；备份失败时拒绝写入，避免覆盖唯一副本
- **启动清理不再误删正在阅读的那一期**（旧版可能连同阅读进度一起删掉）
- 在线更新解压时**拒绝符号链接条目**，避免恶意包写穿插件目录

## 交互体验

- 每个源在**发出第一个网络请求之前**就显示「正在连接 X…（点击可取消）」——旧版在弱网下会有长达一两分钟毫无反应的"假死"
- 某个源抓取失败时，完成提示里会写明「**本期未取到：源A、源B**」，不再默默少内容
- 修复「往期缓存」列表里同一天合并期排序错乱的问题

## 兼容与工程

- 发行包顶层目录本版起为 `zhifou.koplugin/`（v0.1.13 及更早的设备更新器两种目录名都接受，可正常在线升级）
- 测试增至 **13 个 spec / 545 项断言**，`luacheck` 零告警；发布脚本加了发布前门禁（测试 + 静态检查不过不发版）

## 已知边界

知乎部分图片是「`.jpg` 的 URL 里装 PNG 字节」，其 CDN 忽略转格式参数，只能按原样收录（本期约 3.5MB 属于这类）。判型与显示都正常，仅体积压不下去。
